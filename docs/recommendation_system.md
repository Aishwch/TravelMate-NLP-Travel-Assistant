# Recommendation System Design — TravelMate

## 1. Overview
The TravelMate Recommendation System ranks destinations dynamically based on natural language constraints. Rather than returning static database dumps, the engine calculates a composite relevance score across 8 dimensions and attaches natural language justifications explaining the decision.

---

## 2. Dynamic Weight Adaptation

Depending on which constraints are actively present in the user query, the scoring weights adjust dynamically:

| Dimension ($S_i$) | Default Weight ($w_i$) | Trigger Condition | Adjusted Weight ($w_i'$) |
| :--- | :--- | :--- | :--- |
| **Semantic Similarity** ($S_{\text{sem}}$) | 0.30 | Open-ended queries without explicit entities | 0.40 |
| **Preference Match** ($S_{\text{pref}}$) | 0.20 | Explicit leisure preferences detected | 0.25 |
| **Category Alignment** ($S_{\text{cat}}$) | 0.10 | General travel | 0.10 |
| **Budget Compatibility** ($S_{\text{bud}}$) | 0.10 | User specifies budget in query ($B > 0$) | **0.25** |
| **Traveler Rating** ($S_{\text{rat}}$) | 0.10 | General travel | 0.10 |
| **Duration Fit** ($S_{\text{dur}}$) | 0.05 | User specifies trip duration ($D$ days) | **0.15** |
| **Season Alignment** ($S_{\text{sea}}$) | 0.05 | User specifies season/month | **0.15** |
| **Accessibility / Mobility** ($S_{\text{acc}}$) | 0.05 | User travels with parents or requires low walking | **0.20** |

---

## 3. Mathematical Scoring Formulations

### Budget Compatibility Score ($S_{\text{bud}}$)
Given user total budget $B$, trip duration $D$ days, and party size $P$ people:
$$\text{Estimated Total Cost } C = \text{DailyTariff} \times D \times P$$
$$\text{Cost Ratio } R = \frac{C}{B}$$
$$S_{\text{bud}} = \begin{cases}
1.0 & \text{if } R \le 0.90 \quad \text{(Comfortable surplus)} \\
0.85 & \text{if } 0.90 < R \le 1.15 \quad \text{(Fits within 15% tolerance)} \\
0.50 & \text{if } 1.15 < R \le 1.40 \quad \text{(Moderately above budget)} \\
\max\left(0.1, 1.0 - (R - 1.0) \times 0.5\right) & \text{if } R > 1.40 \quad \text{(High budget penalty)}
\end{cases}$$

### Physical Accessibility Score ($S_{\text{acc}}$)
For users traveling with elderly parents or requesting minimal walking:
$$S_{\text{acc}} = \begin{cases}
1.0 & \text{if } \text{walking\_level} = \text{'Low'} \\
0.6 & \text{if } \text{walking\_level} = \text{'Moderate'} \\
0.2 & \text{if } \text{walking\_level} = \text{'High'} \quad \text{(Steep steps/treks penalized)}
\end{cases}$$

### Semantic Similarity Score ($S_{\text{sem}}$)
Derived from normalized dense embedding vectors generated by `all-MiniLM-L6-v2`:
$$S_{\text{sem}} = \frac{\vec{q} \cdot \vec{d}}{\|\vec{q}\|_2 \|\vec{d}\|_2} \in [0.0, 1.0]$$

---

## 4. Transparent Explainability Generation

For every recommended destination, the engine inspects the contributing score components and synthesizes clear, evidence-based bullet points:

* **Budget Rationale**: `✓ Fits your ₹8,000 budget comfortably (est. ₹1,800/day per person)`
* **Duration Rationale**: `✓ Ideal duration (2 days) matches your 2-day timeframe`
* **Mobility Rationale**: `✓ Low walking & flat terrain — exceptionally comfortable for elderly parents`
* **Serenity Rationale**: `✓ Peaceful, uncrowded atmosphere free from overwhelming tourist rush`
* **Preference Rationale**: `✓ Matches your interests in Nature, Photography, and Waterfalls`
